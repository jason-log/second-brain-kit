# 역할 분담과 검수 원칙

큰 작업은 한 맥락에서 끝내지 않고, 역할을 나눈 서브에이전트에 맡긴다. 메인 세션(오케스트레이터)은 지시서(brief)를 쓰고, 결과를 검토해 승격 여부를 판정한다.

## 역할

| 역할 | 하는 일 | 하지 않는 일 |
|---|---|---|
| explorer | 지정 범위를 훑어 원자료를 수집·목록화 | 해석·권고 |
| analyst | 원자료를 brief의 기준으로 구조화·비교·해석 | 원자료에 없는 수치 생성 |
| writer | 자료와 구조 지시에 따라 초안 작성 | 출처 없는 인용 |
| verifier | 수치·인용·날짜·고유명사를 원본과 전수 대조 | 논리·문체 평가 |
| critic | 논리·구조를 적대적으로 검수 | 개별 수치 대조 |

역할 정의는 `agents/`에 있다.

## 원칙

1. **검수는 새 맥락에서.** 작성한 맥락은 자기 가정에 오염되어 있다. 수치·인용을 담거나 남에게 나가는 산출물은 작성 과정을 모르는 새 맥락의 verifier·critic을 거친다.
2. **에이전트 산출물은 바로 사실로 올리지 않는다.** 서브에이전트가 낸 수치·인용·판정은 표본을 원본과 직접 다시 대조한 뒤에만 사실로 쓴다. 검수 결과도 마찬가지로 재현해 "승격"과 "반증"을 갈라 보고한다.
3. **brief에 맥락을 전부 담는다.** 서브에이전트는 대화를 모른다. 읽을 파일 경로, 범위(포함·제외), 출력 경로와 형식, 판단 기준을 명시한다. 수치가 있으면 **분모(기저)**를, 원고 고유 용어가 있으면 그 목록을 함께 적는다. 이것이 빠지면 정상 값을 오류로 판정한다.
4. **막히면 멈추고 보고한다.** 같은 오류가 반복되거나 접근이 수렴하지 않으면 억지로 완성하지 않고 현재 상태와 막힌 지점을 보고하게 한다.
5. **비용에 맞춰 모델을 고른다.** 기계적 대조는 작은 모델, 의미 판단이 필요한 검수는 큰 모델에 배정한다.

양식은 `templates/brief.md`.
