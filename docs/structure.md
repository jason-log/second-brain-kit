# 구조 — 누가 썼고 얼마나 믿는가

볼트를 주제가 아니라 **누가 썼고 얼마나 믿을 수 있는가**로 나눈다. AI는 세션이 끝나면 대화를 기억하지 못하므로, 볼트가 곧 AI의 장기 기억이다. 사람이 보관하는 서고가 아니라 AI가 빨리 읽고 정확히 찾는 작업 기억으로 설계한다.

## 층

| 폴더 | 담는 것 | 쓰는 쪽 | 신뢰 처리 |
|---|---|---|---|
| `sources/` | 원본(논문·기사·자료)과 그 목록. 큰 파일은 위치만 적는다 | AI가 등록, 내용은 고치지 않음 | 사실 확인의 유일한 근거 |
| `wiki/` | 개념·대상·주제 쪽. 사실 문장마다 `(출처ID·등급)` | AI | 자율 + 작업 단위 커밋 |
| 작업 폴더(예: `projects/`) | 진행 중인 일과 그 상태(`handoff.md`·`state.json`) | 함께 | 프로젝트 규칙 문서를 따른다 |
| `log/` | 날짜별 사건 기록 `YYYY-MM.md`. 추가만 한다 | AI | 자율 |
| `inbox/` | 마찰 없는 수집함 | 사람 | 비우는 것이 원칙 |
| `me/` | 나의 선호·문체·판단 기록 | AI가 제안, 사람이 승인 | 제안 후 반영 |
| `system/` | 운용 규칙·도구 | AI가 제안, 사람이 승인 | 제안 후 반영 |

볼트 맨 위의 `CLAUDE.md`(또는 `AGENTS.md`)가 진입 문서다. AI는 세션마다 이 문서 → 규칙 → 선호 순으로 읽고 맥락을 복원한다. 진입 문서는 지도만 담고 짧게 유지한다.

## 사실 문장의 단위

위키의 지식 최소 단위는 **출처가 붙은 주장**이다.

```
- Darvishi 외(2024)는 10개 강좌 1,625명을 대상으로 무작위 통제 실험을 했다 (S-0003 p.1·확인함)
```

등급은 `확인함 / 추정 / 미확인` 세 가지다. 이 표기가 모순 탐지, 낡은 주장 갱신, 원문 표본 대조를 기계적으로 만든다.

## 세 연산

| 연산 | 내용 |
|---|---|
| 수집(ingest) | 원본 등록 → 요약 쪽 → 관련 개념·대상 쪽 갱신 → 색인·기록. 원본 1건 = 커밋 1개 |
| 질의(query) | 색인 → 관련 쪽 → 출처를 단 답. 가치 있는 답은 위키 쪽으로 저장 |
| 점검(lint) | 모순·낡은 주장·고아 쪽·출처 없는 문장, 무작위 표본 원문 대조. 주 1회 |

## 권한 3단계 — 허가가 아니라 검토로 신뢰한다

| 단계 | 대상 | 처리 |
|---|---|---|
| 자율 | 위키·기록·작업 상태·다시 만들 수 있는 산출물 | AI가 처리하고 작업 단위로 커밋 |
| 제안 후 승인 | 규칙·선호·진입 문서 | 바뀌는 문장을 전후 3줄 diff로 보이고 승인받음 |
| 사전 승인 | 외부 발송·반출, 원본 삭제, 내용이 사라지는 덮어쓰기, 남에게 나가는 산출물 확정 | 실행 전에 반드시 확인 |

## 세션 운용

- 착수: 진입 문서 → 프로젝트 규칙 → `handoff.md`·`state.json`을 읽고 시작한다.
- 확정 즉시 저장: 대화로 확정한 문안은 절 단위로 바로 파일에 쓴다(세션 압축으로 잃지 않도록).
- 종료: `handoff.md`(한 줄 현황·다음 할 일·미결·재시도 금지)와 `state.json`을 갱신하고, 다음 세션에 붙여넣을 착수 프롬프트 한 개를 남긴다.

## 기억해 둘 위험

- 합성 오류의 누적이 가장 큰 위험이다. 출처·등급과 주기적 표본 대조로 줄이되, 남에게 내는 산출물은 원문으로 확정한다.
- 시스템 자체가 일이 되는 위험. 구조를 손보는 데 드는 시간을 따로 잰다.
